# 작업 시작·재개

1. Root `AGENTS.md` → 이 문서 → `진행현황.md` → 해당 `projects/*.md` → `architecture/결정기록.md` 순서로 읽는다.
2. Node 24 LTS와 Git을 준비한다. 저장소는 `https://github.com/codelily98/blog-codelily.git`이며 `main`을 사용한다. 기존 MIT LICENSE와 초기 이력을 보존한다. 새 PC에서는 저장소를 clone/pull하고 소스·lockfile·migration·문서를 함께 동기화한다. 커밋 메시지는 한글로 작성한다.
3. 새 PC에서는 `npm ci`, `node scripts/setup-local.mjs`로 로컬 전용 secret과 환경 파일을 준비하고 `docker compose up -d --wait`로 PostgreSQL·Redis를 시작한다. Google/R2 실제 secret은 별도 안전한 경로에서 전달한다. `.env.local`·`.env.migrate.local`·`.local/`·`infra/secrets/`는 commit 대상이 아니다.
4. `npm run db:migrate`, 개발 샘플이 필요할 때만 `npm run db:seed`를 실행한다. host 개발은 `npm run dev`, 전체 컨테이너 미리보기는 `docker compose --profile web up -d --build --wait`다. 둘은 같은 3000 포트를 동시에 사용하지 않는다. Docker 없이 DATABASE_URL을 비운 개발 환경은 PGlite를 사용하며 운영은 실제 PostgreSQL만 허용한다.
5. 작업 전 문서의 다음 단계·미검증 사항을 확인하고 실제 코드 상태를 읽는다. 체크박스만 보고 완료를 추정하지 않는다.
6. 작업 후 `npm run typecheck`, `npm run check:boundaries`, `npm test`, `npm run build` 및 변경 경로의 브라우저 검사를 수행한다.
7. 종료 전에 `진행현황.md`와 프로젝트 문서에 날짜, 변경 파일/범위, 실행 명령·결과, 남은 문제, 다음 시작점을 기록한다. 비밀값·개인 사용자 데이터·PC별 절대경로를 기록하지 않는다.

프로젝트 순서: `common-react` → `code-lily` → `admin-dashboard` → `resume-site` → `intro-page`. 각 단계는 공통 모듈이 실제 두 번째 소비자에서도 재사용되는지 확인하며 확장한다.

문서는 이어서 작업할 계약이며 실행 로그의 진실성을 우선한다. 외부 OAuth·DNS·R2 등 계정 설정이 필요한 항목은 “구현 완료 / 운영 검증 대기”로 구분한다.
