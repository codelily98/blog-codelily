# 디자인·공통 컴포넌트 기준

화면 원본: [Posts](references/posts-reference.png), [About](references/about-reference.png). 구현용 [Posts 콘셉트](references/posts-concept.png)는 ImageGen으로 작성했다. 글과 개인 이력은 복제하지 않고 code-lily의 자체 예시 콘텐츠로 구성했다.

## 토큰·구조

- 다크 배경 `#171614`, surface `#211f1c`, 본문 `#eeece5`, 보조 글자 `#aaa59b`, 구분선 `#36332d`.
- 라이트 배경 `#faf9f6`, surface `#f0eeea`, 본문 `#24221f`, 보조 글자 `#67635d`, 구분선 `#d8d5cf`.
- 공통 header: 로고·Posts·About·검색·테마·Google 로그인. 권한이 있으면 내 Posts 진입점 추가.
- 전체 너비 1168px(좌우 24px 포함), sidebar 240px와 48px 간격. 768px 아래는 한 열, 카테고리는 별도 가로 스크롤 영역.
- 카드는 2열에서 모바일 1열, 제목·날짜·분류·요약·태그 순서. About은 좁은 본문, 경력은 기간/직무 행, 관심사는 chip, 연락처는 link.
- 버튼·입력은 기본 44px, 작은 태그는 최소 32px. 키보드 focus와 reduced-motion을 공통으로 처리한다.

## 레퍼런스와의 의도적 차이

brand/아이콘·글·소개 문구는 code-lily 소유 내용으로 변경했다. 원본의 더 옅은 보조 글자 대신 대비를 높였고, 조작 영역을 키웠다. 작은 화면 header는 메뉴를 두 번째 줄로 옮겨 가로 넘침을 없앴다. About의 실제 경력·공개 연락처는 사용자가 별도로 확정해야 한다. 빈 데이터에 임의의 업무 성과나 사용자 통계를 생성하지 않는다.

## 시각 검수 항목

1. 다크 팔레트·구분선·낮은 채도의 카드가 일관적인가.
2. Header와 main의 가운데 정렬, sidebar/2열 카드 비율이 유지되는가.
3. 제목·요약·메타·태그의 크기와 행간이 읽기 쉬운가.
4. About의 좁은 본문·항목별 디자인이 레퍼런스의 정보 계층을 유지하는가.
5. 라이트 테마와 390px 화면에서도 가로 넘침·잘림·초점 누락이 없는가.
6. 실제 제어가 검색·필터·상세·작성·테마·모달로 연결되는가.

최종 검수는 원본/콘셉트와 브라우저 screenshot을 함께 확인한다. 자동 axe 검사와 별도로 글꼴·여백·색·레이아웃·모바일 변형을 비교하고, 실제 검증 결과는 진행현황에 기록한다.
