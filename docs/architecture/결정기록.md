# 아키텍처 결정 기록

## ADR-001: 저자원 Next.js 서비스

서비스마다 Next.js standalone 프로세스 하나를 두고 DB·Redis는 공유한다. 초기 구현은 code-lily 한 앱이며 이후 resume-site, intro-page, admin-dashboard를 독립 배포한다. 서비스별 스키마·역할·migration·세션을 소유한다. 다른 앱의 테이블·코드를 직접 참조하지 않는다. 공통 React 패키지는 특정 앱을 알지 못한다.

앱의 기능 모듈은 `domain`(모델·정책·port), `application`(use case), `infrastructure`(DB·외부 SDK), `presentation`(React)으로 나눈다. 의존성 연결은 `src/composition.ts` 한곳에서 수행한다. Route Handler/Server Action은 DTO 검증·세션·오류 변환 후 application을 호출한다. 인증과 소유권 정책은 UI 숨김에 의존하지 않는다. NestJS decorator/DI container 없이 명시적 생성자 주입으로 같은 책임 분리를 구현한다.

복잡한 범용 프레임워크를 새로 만들지 않는다. 테이블당 service를 기계적으로 만들거나 하나의 거대 service에 모든 기능을 넣지 않는다. 순환 의존·앱 간 import·공통 패키지의 앱 의존은 경계 검사에서 실패시킨다.

## ADR-002: 공유 React workspace

`packages/ui`: Button·Field·Dialog·Toast·Spinner·테마·토큰. `editor`: SunEditor의 client-only 생명주기와 HTML/Markdown 편집. `content`: 서버 정제·Markdown 변환. `charts`: react-chartjs-2와 동일 데이터의 텍스트 표. `grid`: Tabulator와 접근 가능한 표. `storage`: S3 API/R2. `contracts`: 서비스 간 버전 계약.

패키지는 source export와 `transpilePackages`로 소비한다. npm workspaces와 고정 lockfile을 사용한다. 필요할 때 패키지별 빌드·버전 배포로 확장할 수 있다. 에디터·차트·그리드는 쓰는 화면에서만 lazy load한다. 공개 블로그가 관리자용 라이브러리를 전부 다운로드하지 않게 한다.

## ADR-003: DB와 인증

명시적 SQL repository와 `pg` Pool을 사용한다. 이전 설계 문서의 Prisma 권장은 대체한다. 소규모 도메인에서 ORM 생성·엔진 의존을 줄이고 adapter port로 저장소를 교체할 수 있게 한다. migration은 버전 SQL이며 운영에서 앱 시작과 분리한다. 앱당 pool max 5, 초기 4앱 기준 20개에 배포·운영 여유를 추가하고 PostgreSQL max_connections=60부터 측정한다.

Google 전용 Better Auth를 사용하고 비밀번호 회원가입을 열지 않는다. PostgreSQL에 세션·사용자를 저장한다. Google의 검증된 이메일과 서버 allowlist로 최초 OWNER를 지정하고, 나머지는 MEMBER다. OWNER는 모든 콘텐츠·About·권한을 관리, EDITOR는 자신의 카테고리/Posts 작성·수정, MEMBER는 댓글 작성·자기 댓글 삭제를 할 수 있다. OAuth 설정이 없으면 로그인 상태를 위조하지 않고 설정 필요를 표시한다. 테스트용 권한 우회 endpoint는 운영 앱에 만들지 않는다.

개발용 PGlite는 임베디드 PostgreSQL로 같은 SQL을 사용하며 `.local/`에 저장한다. 운영에서는 `DATABASE_URL`의 실제 PostgreSQL만 허용한다. PGlite는 다중 프로세스 운영·운영 세션 용도가 아니다. 하나의 프로세스에서 transaction을 안전하게 직렬화하는 adapter를 사용한다.

## ADR-004: 콘텐츠와 업로드

Post/About 항목은 원본 source, format(HTML/MARKDOWN), 정제된 HTML을 분리한다. Markdown은 GFM으로 변환하고 HTML은 허용 태그·속성·CSS만 보존한다. script·event handler·iframe·임의 CSS URL을 금지한다. SunEditor 콘텐츠 스타일을 읽기 화면에도 적용하되 편집기 UI 스타일을 전역으로 퍼뜨리지 않는다. 코드·표·인용·제목·목록·이미지가 정상 표시되어야 한다.

Cloudflare R2는 S3 호환 API로 접근한다. 공개 이미지는 public bucket + `media.codelily.kr` 같은 사용자 지정 도메인/CDN, 이력서·원본 파일은 private bucket + 권한 검사 후 서명 GET을 사용한다. 업로드 서명 URL은 S3 API endpoint로 발급하며 custom domain용 URL로 변조하지 않는다. URL 유효기간·MIME·크기·quota·소유권을 검증하고 업로드 완료 시 HEAD로 실제 크기·metadata를 확인한다. 이미지 공개 전에 서버 검증이 끝나야 하며 미참조 파일은 수명 정책으로 정리한다.

## ADR-005: 통계·사용자 발자취·로그

사용자 발자취는 동의한 브라우저의 페이지 경로·시각·이벤트 종류만 수집한다. query string·원문 IP·입력값·이력서·토큰·댓글 내용은 수집하지 않는다. 서버가 발급한 난수 식별자를 HMAC 처리하고 짧은 보존 기간을 둔다. 경로 event는 서버 allowlist로 제한하고 크기·빈도 제한을 둔다. 분석 동의 거부 시 browsing 수집을 중지한다. 업무 감사·인증 보안 로그와 선택적 분석은 분리한다.

초기 code-lily 내부 관리 화면에서 실제 DB 이벤트·감사 로그를 Chart/Grid로 조회한다. 별도 통합 admin은 `/api/internal/v1/summary` 같은 버전 계약으로 앱별 집계만 가져오며 토큰·audience·deadline을 검증한다. 다른 앱 스키마를 admin이 직접 조회하지 않는다. 원본 이벤트 30일, 운영 로그 14일, 감사 로그 90일을 초기 정책으로 제안하고 실제 운영 요구에 맞춰 확정한다. 정리는 별도 제한된 운영 작업으로 수행한다.

## ADR-006: 자원·HTTPS·CDN

8GB 기준 초기 상한: code-lily 512MiB, 추후 resume/intro 각 512MiB, admin 640MiB, PostgreSQL 1536MiB, Redis 256MiB(maxmemory 128MiB), Caddy 192MiB, cloudflared 128MiB. 4앱과 Redis를 모두 포함한 구성 합계 4288MiB, 나머지는 OS·캐시·배포·운영 여유다. 현재 code-lily 단독 구성은 Redis 미사용 시 2368MiB 상한 합계이며 실측 사용량이 아니다. 메모리 증대는 CPU 2개 병목을 없애지 않는다. CI에서 빌드하고 PDF 렌더링·큰 이미지 변환은 별도 처리한다. 통계 조회는 기간·row 한도를 강제한다.

Cloudflare 프록시/WAF → Tunnel → Caddy HTTPS → Next.js. Cloudflare Full (strict), Caddy DNS-01 `caddy-dns/cloudflare`, 제한된 DNS token과 영속 `/data`로 인증서 자동 발급·갱신. `blog`는 Tunnel이 제공하는 CNAME으로 연결하며 원본 서버의 웹 포트와 IP 우회 경로를 공개하지 않는다. DNS/계정 변경은 운영자가 수행할 항목으로 남긴다.

CDN 기본 대상은 해시 정적 자산·공개 R2 미디어다. 외부 JS CDN을 쓴다고 앱 비용이 자동 절감되는 것은 아니므로 라이브러리는 npm으로 고정·자체 빌드하고 Cloudflare가 빌드 파일을 캐시한다. 회원/관리자/댓글 쓰기·인증 응답은 no-store다. HTML/RSC 캐시는 초기에는 Cloudflare에서 강제 cache-everything하지 않는다. 공개 JSON/HTML 캐시를 추가할 때 인증 쿠키·RSC variant·공개 해제 즉시성·purge를 먼저 검증한다.
