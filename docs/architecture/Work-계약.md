# Work 기능 계약

2026-11-05 기준. Work는 `code-lily`가 소유하는 단일 업무 문서 공간이다. 등록·변경·이동·삭제·복구·업무일지 생성은 OWNER만 수행한다. MEMBER와 EDITOR는 로그인 후 공개된 항목을 조회·검색·열람한다. 일반 회원에게 제공하는 문서 응답은 정제된 HTML과 문서 정보이며 원문 필드는 빈 문자열이다.

## 공개와 저장

- 새 폴더·문서는 비공개다. 문서와 모든 상위 폴더가 공개이고 삭제되지 않은 경우에만 회원에게 표시한다. 폴더 공개 전환은 하위 항목의 개별 공개 설정을 유지한다. 문서의 공개 설정은 이후 저장되는 내용에도 적용된다.
- `/work`, `/work/document/{uuid}`의 비로그인 접근은 로그인 화면으로 연결하며, 로그인 뒤 Work 메뉴에서 접근한다. 페이지는 동적 렌더링하고 검색 엔진 색인을 막는다. API 성공·오류 응답은 공통 `private, no-store` 계약을 사용한다.
- Markdown 원문은 `work_document.content`에 저장한다. SunEditor의 공통 Markdown 전용 모드가 원문을 편집하고 서버의 공통 GFM 변환·정제로 미리보기를 만든다. Work 미리보기에는 외부 이미지 태그를 포함하지 않는다. 첨부 업로드는 후속 범위이며 기존 Posts/About 이미지 동작은 공통 기본 옵션을 따른다.
- Work 편집 영역의 배경과 글자색은 사이트 테마를 따른다. 줄 번호와 하단 크기 조절 막대는 표시하지 않는다. 긴 줄은 편집 영역 너비에 맞춰 표시상 줄바꿈하며 저장되는 원문에는 줄바꿈을 삽입하지 않는다. 자동 저장·글자 수 제한·Markdown 기능·저장 단축키는 기본으로 접힌 ‘편집 안내’에서 확인할 수 있다.
- 자동 저장은 한글 조합 종료 후 마지막 입력에서 1.5초가 지난 시점에 시작한다. 문서별 요청을 직렬화하고 요청 중 생긴 후속 변경도 저장한다. Ctrl/Cmd+S와 저장 버튼으로 즉시 저장할 수 있다.
- 저장 요청은 기준 `version`을 필수로 보내며 DB에서 비교·갱신·증가를 한 문장으로 처리한다. 충돌은 409이며 로컬 원문을 유지한다. 서버 원문과 저장할 원문을 비교해 명시적으로 병합한 뒤 최신 기준 버전으로 저장한다. 응답이 유실된 저장도 원문 비교를 통해 해결할 수 있다.
- 문서 선택과 앱 링크 이동은 저장 완료를 기다린다. 미저장 상태의 브라우저 이력 이동은 편집 위치를 복원한 뒤 저장에 성공하면 이동한다. 이 과정에서 앞으로 가기 이력이 재구성될 수 있다. 새로고침·탭 종료는 브라우저 이탈 확인을 사용한다. 브라우저 강제 종료 후 원문 복구는 보장 범위에 포함하지 않는다.

## 데이터·동시성·보존

- `006_work.sql`은 `work_space`, `work_node`, `work_document`와 제한된 휴지통 정리 함수를 추가한다. 사용자 FK는 기존 TEXT ID를 참조하고 문서·노드는 UUID, 시각은 TIMESTAMPTZ를 사용한다. 기존 테이블 데이터를 변경하는 migration은 포함하지 않는다.
- 단일 `work_space` 행을 잠근 뒤 모든 쓰기를 수행한다. 트리 변경에는 `treeVersion`도 필수다. 같은 버전의 동시 이동 중 먼저 완료한 변경만 반영하고, 후속 요청은 409로 거절한다. 순환·문서 부모·삭제된 부모·최대 깊이를 잠금 안에서 검사한다. 같은 공간의 문서 저장도 같은 잠금 순서를 사용한다.
- 최대 깊이는 7단계, 휴지통 포함 최대 2,000개 항목, 이름은 1~200자, Markdown은 최대 100,000자다. 이름은 공백 제거·Unicode 정규화 후 검증하고 같은 부모의 활성 이름은 중복을 허용하지 않는다. 형제 순서는 이동 시 서버에서 재배치한다. 검색은 접근 가능한 이름의 부분 일치이며 최대 50건을 반환한다.
- 폴더 삭제는 현재 활성 하위 트리를 하나의 삭제 묶음으로 처리한다. 먼저 개별 삭제된 하위 항목은 별도 묶음으로 유지한다. 삭제·복구 시 관련 문서 버전도 증가시켜 오래된 편집 요청을 거절한다.
- 휴지통 복구 기간은 30일이다. 원래 부모가 활성 상태이면 그 아래로, 없으면 최상위로 복구한다. 이름 충돌에는 `(복구 번호)`를 붙이며 복구 묶음 전체를 비공개로 전환한다. 복구 후 최대 깊이도 다시 검사한다.
- 기존 유지보수 실행에 `prune_work_trash()`를 연결한다. 30일이 지난 하위 항목 없는 노드를 회당 최대 500개 정리하므로 깊은 트리는 여러 실행에 걸쳐 제거된다. 본문은 FK로 함께 제거된다. maintenance는 함수 실행만 허용하고 Work 테이블 직접 조회는 허용하지 않는다. runtime은 정리 함수를 실행하지 못한다.
- 업무일지는 한국 표준시의 날짜당 하나다. 이름·위치가 바뀌어도 `journal_date`로 재사용하며 휴지통에 있으면 복구를 안내한다. 업무일지·연도·월 폴더는 안정적인 `system_key`로 재사용한다. 프로젝트 정리는 일반 폴더와 문서로 제공한다.
- Work 작성자는 OWNER이며 기존 회원 관리 화면에서 OWNER 강등·탈퇴를 제공하지 않는 정책을 따른다. 유지보수·백업에는 Work 테이블이 함께 포함된다. 향후 운영자 계정 이관 또는 탈퇴를 도입할 때 작성자 FK와 문서 보존 계약을 함께 변경한다.

## API

모든 경로는 세션을 검증하며 변경 요청은 기존 Same-Origin 검사를 적용한다. 응답은 기존 `{ data, requestId }`, 오류는 `{ error, requestId }` 계약이다. `error.code=WORK_CONFLICT`는 저장 또는 트리 버전 충돌을 나타낸다.

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| GET | `/api/work/tree` | 권한에 맞춘 트리와 트리 버전 |
| GET | `/api/work/search?q=검색어` | 문서·폴더 이름 검색 |
| POST | `/api/work/nodes` | 이름·유형·부모·트리 버전으로 생성 |
| PATCH | `/api/work/nodes/{id}` | `action`에 따라 rename·visibility·move·delete·restore |
| GET | `/api/work/documents/{id}` | 문서 정보·정제된 HTML·문서 버전 |
| PUT | `/api/work/documents/{id}` | content·version으로 저장 |
| POST | `/api/work/preview` | 현재 content의 서버 미리보기 |
| GET | `/api/work/trash` | 복구 가능한 삭제 묶음과 트리 버전 |
| POST | `/api/work/today` | 오늘 업무일지 조회 또는 원자적 생성 |

## 인수 조건

- 비로그인 API 401, MEMBER·EDITOR 변경 403, 비공개·삭제 문서 읽기 404와 검색 제외를 확인한다. 하위 문서만 공개해도 비공개 상위 폴더로 접근을 우회할 수 없어야 한다.
- Markdown의 Front Matter·코드·체크 목록·내부 링크 문자열을 저장·재열기해 원문 보존을 확인한다. 완료 체크는 완료 상태와 접근성 이름을 유지한다. 스크립트·이벤트·악성 링크는 렌더링하지 않는다.
- 편집기에서 라이트·다크 배경과 글자색 전환, 키보드로 편집 안내 열기·닫기, 긴 줄의 가로 스크롤 없는 표시와 저장 후 원문 보존을 확인한다.
- 두 문서 저장과 서로 반대 방향의 폴더 이동, 업무일지 동시 생성, 삭제·복구 후 오래된 저장 요청을 검증한다. 통신 실패·409 충돌에서 원문 유지·재시도·병합을 확인한다.
- 트리 방향키·Home/End·Enter/Space, 키보드로 가능한 이동 대화상자, 모바일 탐색 대화상자의 초기 초점·Escape·초점 복귀, 저장 상태 안내를 확인한다. 트리 이동은 위치 선택과 순서 입력으로 수행한다.
- 데스크톱과 390px 모바일, 라이트·다크, 가로 넘침·오류 overlay·콘솔 오류와 자동 접근성 검사를 확인한다. 자동 검사 결과와 별도 수동 보조기기 심사를 구분한다.
